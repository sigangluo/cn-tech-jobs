# 社招职位看板

多家互联网公司的**技术 / 产品**社招岗位：各公司官网公开接口 → `data/<公司>/*.csv` → 合并成静态站点数据 → `site/` 看板。README 见 [../README.md](../README.md)。

**公司不是固定的。** 后续会陆续接入新公司，所以任何脚本、页面、文档里都不要写死公司名或公司数量；公司列表唯一的来源是 `companies/` 目录。

## 目录

```
companies/<key>/fetch.py   每家公司只有这一个文件：META（元信息）+ fetch()（抓取）。自动发现
companies/_template/       新增公司的模板（下划线开头的目录不会被当成公司）
scripts/update.py          入口：并行抓取 + 合并
scripts/fetch_company.py   抓取单家公司 → 校验 → 写 data/<key>/<类别>.csv（update.py 调它；调试新公司时也可单独跑）
scripts/build.py           data/*/*.csv → site/data
scripts/lib/               共用代码：schema.py（统一职位格式）、years.py（年限识别）、http.py、companies.py（自动发现）
data/<key>/<类别>.csv      抓取产物（每家每个看板类别一个文件）
site/                      静态看板；site/data/ 全是生成物，不要手改
```

## 用户说「更新一下数据」时，照这个流程走

每周一的固定流程。全程是确定性脚本，不需要 LLM 判断，也不需要任何 API key。

```bash
python3 scripts/update.py        # 并行抓取所有公司 + 合并，约 6 分钟（取决于最慢的一家）
```

1. **看输出**：每家应该显示「完成」。任何一家「失败」都会中止且不合并，按提示 `--only <key>` 重抓，再 `python3 scripts/update.py --build-only`。
2. **核对数量**：最后会列出各公司技术 / 产品数量。某家出现 `⚠ 职位数 A -> B，减少超过 30%`（抓取时和覆盖前的 CSV 比）多半是抓取不全而不是真的下架——先重跑那一家，仍然少再去查接口是否变了，**不要直接接受**。
   看板只呈现每周一当下在招的岗位：不保存历史，不做新增 / 下架对比，也没有趋势图。
3. **本地预览**：`python3 scripts/serve.py`，看一眼页面。不能直接双击 html，`fetch` 会被 file:// 拦住；也不要用 `http.server`，它会让浏览器缓存旧数据。
4. 告诉用户这周的结果：各公司职位数、有没有 ⚠。**不要自动 commit / 推送 / 发布**，除非用户明确要求。

## 发布

`main` 分支只放代码（`data/` 和 `site/data/` 被 `.gitignore` 忽略）。数据由 `scripts/publish.py` 单独发布到 `gh-pages` 分支，那个分支**永远只有一个提交**，线上只有当前这一份。

- 用户说「发布」时：先运行 `python3 scripts/publish.py`（默认只构建和检查，不推送），把要发布的文件数、数据日期、提交作者、目标仓库告诉用户，**得到确认后**才加 `--push`。强制推送会覆盖线上内容，属于对外发布。
- 提交作者用本仓库 `git config` 里的公开身份（GitHub noreply 邮箱），不要用内网 / 公司邮箱。
- 改了 `scripts/lib/years.py` 或 `schema.py` 后先跑测试：`python3 -m unittest discover -s tests`。

## 新增一家公司

只需要写一个文件，其余（合并、看板、页脚说明）全部自动带上。

1. `cp -r companies/_template companies/<key>`，`<key>` 用公司英文名小写（它同时是 `data/<key>/` 的目录名）。
2. 在浏览器 F12 → Network → Fetch/XHR 找到返回职位列表的接口，Copy as cURL。先确认**不带 cookie 是否也能调通**、单页最多多少条、翻页有没有上限（有的站点搜索最多翻到 1 万条，有的翻页会漏项）。
3. 改 `fetch.py` 里的 `META` 和 `fetch()`。`fetch()` 返回 `make_job(...)` 的列表（字段说明见 `scripts/lib/schema.py`）：
   - 接口有结构化年限就直接填 `years`；只有任职要求文本就用 `parse_years(text)` 识别。
   - 公司特有的信息（学历、业务线……）放进 `extra`，只进 CSV，不进看板。
   - 想让这家公司有自己的筛选（比如二级类别、业务线、部门）就在 `META["facets"]` 里声明 `[(显示名, 数据来源)]`，来源是 `"subcategory"`、`"dept"` 或 `extra` 里的列名。挑区分度高的（十几到几十种取值）；看板只在选中这一家公司时才显示这些下拉框。
   - `category` 填公司**原始的**一级分类名，不要在 `fetch()` 里自己合并；多个原始分类合成一个看板类别，靠 `META["categories"]` 多对一映射（如 `{"技术类": "技术", "LB技术": "技术"}`）。这样看板才能显示每个看板类别来自公司的哪些原始分类。
   - 抓不全就**抛异常**，不要返回半截数据；`call_json` 已经带重试，失败会抛 `FetchError`。
4. `python3 scripts/update.py --only <key>` —— 会抓取、校验、写 CSV 并合并。校验不通过（id 重复、日期格式不对、某个类别一条都没抓到……）会直接说明原因。
5. 打开预览确认公司出现在筛选、图表和列表里；点开一个职位看看描述，确认链接能打开（没有把握的链接宁可留空）。

不要为新公司改 `build.py`、`update.py`、`site/` 或这份文档。如果发现必须改才能接入，说明抽象漏了——先补 `lib/`，不要给某家公司开特例。

新增**看板类别**（比如「运营」）才需要动共用代码：`scripts/lib/schema.py` 的 `CATEGORIES` 加一项，各公司 `META["categories"]` 里映射过来即可，前端最多支持 8 个类别，颜色按顺序自动分配。

## 通用筛选与公司专属筛选

看板的筛选分两层：**通用层**（时间、公司、类别、城市、年限、搜索）对所有公司一致，用于跨公司对比；**公司层**由各公司 `META["facets"]` 声明，只选中**一家**公司时自动出现（多家公司的取值混在一起没法选，切换公司会清空）。专属维度不需要改前端——前端只读 `jobs.json` 里的 `companies[].facets` 和每个职位的 `f`。空值统一显示为「（未标注）」。

## 已接入公司的数据差异

各公司自己的怪癖写在各自 `fetch.py` 的注释和 `META["note"]` 里（后者会显示在看板页脚）。共通的几点：

- **类别口径不同**：`META["categories"]` 把公司自己的类别名映射成看板类别（如「研发」→「技术」，可以多对一），只导出映射里列出的类别。原始分类保留在 CSV 的「职位类别」列和 `jobs.json` 的 `rc` 字段，看板的公司卡片会显示「看板类别 ← 原始分类」。各家的类别体系不对等，收录范围写在各自 `META["note"]` 里。
- **日期含义不同**：`META["date_label"]` 说明是「发布时间」还是「更新时间」，CSV 列名和看板页脚都会体现。
- **直达链接必须用真实浏览器验证**：这些站点多是单页应用，任何路径都返回同一个壳页面，curl 判断不了对错。验证方法：在浏览器里打开列表页、点一个职位，看它跳到哪个地址（有的站点还需要额外参数，比如网易要带 `lang=zh`，否则会被跳回首页），再用 Playwright 抽样打开几条自己拼的链接，确认页面上出现对应的职位名。拿不准的留空，看板会指向官网职位列表。已接入公司的详情页地址都已用这个办法验证过。

## 工作年限的识别规则

全部公司共用 `scripts/lib/years.py` 的 `parse_years`，**只有这一份**：

- 支持阿拉伯数字和中文数字（「两年以上」→ 2年以上）；「及以上」统一写成「以上」。
- 年限所在分句里出现「优先 / 为佳 / 加分」，或位于「加分项」「具备以下条件者优先：」这类分节标题之后，算**优先年限**，不算必须。
- 「2026年毕业」「2年内毕业」「近两年」不是工作年限，忽略。
- 没有硬性年限：写了「经验不限」记「不限」，否则记「未提及」。
- `build.py` 再把它换算成「最低年限」（`3-5年以上` → 3），分成 6 档给图表和筛选用（`schema.BUCKETS`）：
  **未提及**（任职要求没写年限，不知道）和**明确不限**（写了不限，或 0-N 年 / N 年以内这类没有最低门槛的要求）是两回事，必须分开；其后是 1-2 / 3-4 / 5-7 / 8 年以上。前端约定第 0 档（未提及）用灰色，其余档用蓝色有序渐变。
- 接口自带结构化年限字段、且写「不限」的，视为明确不限——那是站点自己填的字段。

## 站点

- 纯静态，没有构建步骤、没有第三方依赖、不请求外部资源。公司、类别、年限档位、页头页脚文案全部从 `jobs.json` 读，前端没有任何公司名。
- 职位名、部门、JD 都来自第三方站点：前端**只用 `textContent` / 文本节点渲染**，不拼 `innerHTML`；链接只接受 `https://`。
- 配色遵循 dataviz skill：类别色 `--cat-0…7` 按类别顺序固定分配（技术=蓝、产品=橙），年限用同一色相的有序渐变 `--ord-*`，深色模式方向反过来。两组配色都用 `validate_palette.js` 校验过；改颜色要重跑校验。
- 每张图都有「数据表」视图；悬停提示同样支持键盘聚焦。
