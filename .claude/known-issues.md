不记具体数字（会过期），当前程度读 `reports/<最新日期>.json`。新发现官网本身如此且长期存在的异常补进来（现象、原因、怎么查、为什么接受）；修好了就删条目。

## 官网没给，我们补不出来

**技术 / 产品靠职位名推断**
- 谁：小米、蔚来、小鹏（站点没有类别字段）；理想、智谱、MiniMax、阿里（淘天 / 阿里云 / 盒马等事业群）；京东的「产品」（官网没有产品分类）。
- 页面有「类别推断」标记，`category_inferred_rate` 高（小米、蔚来、小鹏接近 100%）。接受的理由：没有可用字段，推断是唯一办法；规则偏保守，会漏、可能误收，页面已标注并提供「类别来源」筛选。
- 查程度：`category_inferred` 和 `samples.inferred_category`。改规则见 runbook「类别误收 / 漏收」。

**部分公司的职位本身没写工作年限（字节、京东、MiniMax 最明显）**
- 官网任职要求文字里就没写，接口也没有结构化经验字段（字节抽样 100 条全空）。已逐家抽查，不是解析漏识别：京东「未提及」里文字含「N 年」的极少，且是公司介绍里的年份或已被正确归为优先年限；MiniMax 为 0。
- 年限图里这几家灰色占比大，图例已说明灰色不是「不限」。
- 怀疑解析问题时：取该公司「未提及」的职位，在 `site/data/jd/<key>.json` 里搜「N年」字样逐条看上下文。

**智谱：部分职位没有工作城市、少量缺任职要求**
- 官网这些职位的 `locations` 为空（城市有时只在标题里，如「…（成都）」）；不从标题里猜城市，误判比缺失更糟。
- 缺任职要求的是官网只给一个描述字段、没有「任职要求」标题的职位，`lib/jd.py` 找不到边界时保留原文、不猜测，描述里仍有完整内容。

**阿里：部分职位没有直达链接 / 事业群**
- 总站接口不给事业群；事业群站点有的最多返回前 500 条、有的打不开（飞猪是前端路由页）；菜鸟详情页在浏览器里是空白。对应不上事业群的职位拼不出可靠链接，详情里显示「暂无直达链接」，事业群筛选里有「（未标注）」。
- 拼链接的规则在 `companies/alibaba/fetch.py` 的 `DETAIL_TITLE_HOSTS`，加规则前必须在浏览器里验证。

## 范围与口径（有意为之，不是缺陷）

- 各公司「研发 / 技术 / 产品」划分不同，跨公司的技术岗数量只是近似可比；每家的映射在各自 `META["note"]`（页脚显示）。
- 有的公司日期是发布时间、有的是更新时间（`date_label`），「近 7 天」在公司之间不严格可比，页脚已逐家说明。
- 不保存历史：已下架的职位在下次抓取前仍会显示（页面已提示）。

## 基础设施与待决事项

- **weekly-audit 在 GitHub 服务器上抓不到网易**（2026-11-07 验证：连续 4 次返回非 JSON，本机正常，多半是官网拒绝海外机房 IP；其余 16 家可抓）。`update.py` 任何一家失败都会中止不合并，所以只要网易不可达，weekly-audit 每周都会失败、也没有质量报告。已处理：workflow 用 `--allow-failures netease` 跳过它，其余公司照常出报告（报告里没有网易）。如果 CI 上又有别的公司失败，那是新问题，不要往 `--allow-failures` 里加；网易恢复可访问后去掉。（GitHub 上抓取反而更快，阿里约 300s、字节约 130s，说明本机慢主要是网络延迟。）
- 直达链接的验证靠浏览器，没有自动化回归，官网改版后可能悄悄失效；抽查方法见 CLAUDE.md。
- **页面顺序**（职位列表在三张图表之后）取决于产品定位（对比 vs 找工作），尚未决定，不要擅自改。
